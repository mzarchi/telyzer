# Accessibility Statement

## Our Commitment

Telyzer aims to make Telegram analysis tools usable by as many people as possible, including people with disabilities.

We recognize that accessibility is an ongoing process, and we welcome contributions that help make Telyzer easier to use and understand.

## Accessibility Goals

We aim to improve accessibility across all parts of the project.

### Command-Line Interface (CLI)

- Provide clear, descriptive, and consistent command names and help messages.
- Display meaningful error messages and actionable guidance.
- Avoid relying on color alone to communicate important information.
- Use readable output and predictable command behavior.
- Support standard terminal interaction patterns wherever practical.

### Graphical User Interface (GUI)

- Use clear labels and understandable interface text.
- Maintain consistent layouts and navigation patterns.
- Provide sufficient contrast between text and background colors.
- Ensure important information is not communicated through color alone.
- Support keyboard navigation and interaction wherever the underlying framework permits.
- Provide visible focus indicators for interactive elements where supported.
- Use appropriate text sizes and avoid unnecessary visual clutter.

## Assistive Technologies

We aim to improve compatibility with commonly used accessibility features and assistive technologies, including keyboard-only navigation, screen readers, and operating-system accessibility settings.

Actual support may vary depending on the operating system, terminal emulator, and GUI framework.

## Known Limitations

Telyzer is under active development. Some accessibility features may be incomplete, unavailable, or inconsistent across platforms.

We do not currently claim full compliance with any specific accessibility standard.

## Reporting Accessibility Issues

If you encounter an accessibility barrier or have a suggestion for improvement, please open an issue in the [Telyzer GitHub repository](https://github.com/mzarchi/telyzer).

When reporting an issue, please include:

- The affected component (CLI, GUI, or another part of the project).
- Your operating system and relevant environment details.
- The steps needed to reproduce the issue.
- The accessibility barrier you encountered.
- Any suggested improvements, if available.

Please avoid including private information or sensitive user data in public reports.

## Contributing to Accessibility

Contributions that improve accessibility are welcome. Examples include:

- Improving labels, help text, and error messages.
- Fixing keyboard navigation or focus behavior.
- Improving contrast and readability.
- Adding accessible alternatives to color-coded output.
- Improving screen-reader compatibility.
- Documenting accessibility limitations and workarounds.

Please follow the project's contribution guidelines when submitting changes.

## Continuous Improvement

Accessibility is an ongoing effort. We welcome feedback and contributions that help make Telyzer more inclusive and usable for everyone.
